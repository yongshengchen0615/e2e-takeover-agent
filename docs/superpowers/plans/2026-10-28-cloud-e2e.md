# Cloud E2E Implementation Plan — 2026-10-28

## Goal
Move the existing visible E2E handoff workflow to a hosted HTTPS control plane backed by a Browserbase cloud Chromium session. Users should not run a localhost service. Keep admin/multi-client profiles, 390×844 mobile emulation, manual LINE/OTP/test-account sign-in, and resumable test actions.

## Architecture choices
- A: local Playwright and public tunnel — rejected (still needs user's machine).
- B: Netlify-only Functions — rejected (request-bound runtime not suitable for live session orchestration).
- C (selected): Render Node long-lived HTTPS web service + Browserbase remote CDP + Browserbase interactive live debugger. Minimal new infrastructure, one active test per service.
- D: separate job queue, DB, runners, durable multi-tenancy — deferred until concurrent SaaS is required.

## Risks
- Browserbase API key, billed sessions, hosted service account are not connected. Production live browser tests cannot be run until configured.
- Browserbase live debugger URL is a time-limited bearer capability. Only issue to authenticated dashboard users over HTTPS, do not log or persist.
- Third-party web pages including LINE are handled by Browserbase servers. Disable optional recordings/logging, explain provider handling of sessions.
- Render process memory and filesystem are ephemeral; users must provide allowed origins and workspace configuration through secret/environment variables or persistent service storage. One service replica per workspace.
- No automated authorization bypass, no credentials in profiles, no automated login passwords.

## Implementation tasks
1. Add cloud contract tests (server protection, cloud origin allowlist, mobile viewport, take-over and live link). Watch initial red in CI.
2. Implement Browserbase CDP adapter, CloudE2EEngine, HTTPS production server and secured live link API.
3. Extend existing dashboard to use live view; preserve local mode and profile editor.
4. Add Render blueprint, env example, cloud startup docs and security notes.
5. Run full GitHub Actions check/tests, investigate and fix failures, create PR for review.

## Acceptance criteria
- Cloud server binds PORT/0.0.0.0 with healthz and Basic auth on every non-health path.
- Require 24+ character admin secret, exact HTTPS allowlist, CSRF and same-origin writes.
- Cloud session creation with mobile/desktop viewport and recording disabled.
- Manual takeover has no automation, screenshot capture disabled during login, resume same remote browser context.
- Live debugger URL only obtained from authorized protected endpoint with short expiry.
- Full suite passes; cloud vendor E2E remains unverified until real credentials and staging targets are available.
